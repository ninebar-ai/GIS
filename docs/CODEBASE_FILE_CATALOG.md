# Codebase File Catalog

This catalog documents all repository-managed files that are part of product runtime, process governance, documentation, planning memory, and repository operations.

For each file:
- **Purpose**: why it exists.
- **Type**: runtime/process/docs/config/template/etc.
- **Data**: what data it stores, emits, or controls.
- **Provenance**: where the data/content comes from.
- **Primary Consumers**: who reads/uses it.
- **Sensitivity/Operational Notes**: constraints and cautions.

---

## Root and Governance

- `.gitignore` - **Purpose:** exclude non-canonical artifacts. **Type:** repo config. **Data:** ignore rules for datasets, exports, local caches, and `junk/`. **Provenance:** engineering policy decisions. **Primary consumers:** git, contributors, CI. **Sensitivity/Operational notes:** prevents accidental commits of large/sensitive files.
- `README.md` - **Purpose:** root onboarding and runbook index. **Type:** documentation. **Data:** canonical structure, run commands, entrypoints. **Provenance:** maintained by repo owners. **Primary consumers:** new engineers, agents. **Sensitivity/Operational notes:** must stay aligned with path moves.
- `AGENTS.md` - **Purpose:** session contract for AI agents/humans. **Type:** process governance doc. **Data:** read order, commands, non-negotiables, boundaries. **Provenance:** repo-level governance policy aligned to gsd-core-next. **Primary consumers:** coding agents, reviewers. **Sensitivity/Operational notes:** stale instructions can cause workflow drift.
- `USAGE.md` - **Purpose:** compatibility pointer to canonical usage playbook. **Type:** navigation doc. **Data:** redirect and minimal read sequence. **Provenance:** structural redesign decision. **Primary consumers:** humans/agents expecting legacy root path. **Sensitivity/Operational notes:** keep in sync with `process/USAGE.md`.
- `APPROACH.md` - **Purpose:** compatibility pointer to process path guide. **Type:** navigation doc. **Data:** pointer to `process/APPROACH.md`. **Provenance:** structural redesign decision. **Primary consumers:** existing contributors and scripts. **Sensitivity/Operational notes:** prevents broken links from old references.
- `CONTRIBUTING.md` - **Purpose:** contributor workflow and PR standards. **Type:** governance doc. **Data:** branching, verification, handoff expectations. **Provenance:** team engineering standards. **Primary consumers:** contributors/reviewers. **Sensitivity/Operational notes:** mismatch with actual process causes review inconsistency.
- `SECURITY.md` - **Purpose:** security reporting and secure-development policy. **Type:** governance doc. **Data:** reporting path, secret-handling rules, dependency guidance. **Provenance:** team security policy. **Primary consumers:** contributors, maintainers. **Sensitivity/Operational notes:** security-critical operational baseline.
- `CHANGELOG.md` - **Purpose:** track notable changes. **Type:** release/process doc. **Data:** unreleased and released change summaries. **Provenance:** maintained per merged changes. **Primary consumers:** maintainers, reviewers, release coordinators. **Sensitivity/Operational notes:** must not omit impactful behavior or migration changes.
